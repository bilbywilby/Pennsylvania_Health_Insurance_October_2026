## Purpose

This project provides a reproducible pipeline for ingesting, validating, analyzing, and publishing health insurance audit materials. The design favors traceability, deterministic outputs, and modular reuse.

## Detailed Component Specification

### 1) Ingestion Layer

**Purpose:** Collect source material from external systems and preserve raw inputs unchanged.

**Inputs**
- CMS crosswalk pages
- insurer filings
- historical baseline files
- reference tables

**Outputs**
- raw HTML
- CSV extracts
- JSON staging files
- OCR/PDF-derived text

**Primary scripts**
- `fetch_cms_crosswalk.sh`
- `pa_insurer_ingest.sh`
- `legacy_rate_parser.py`
- `verify_cms.sh`

**Rules**
- Never overwrite originals.
- Store each fetch with timestamped provenance.
- Fail closed on malformed source data.

### 2) Normalization Layer

**Purpose:** Convert heterogeneous source files into a canonical schema.

**Canonical output**
- `data/canonical/market_data.json`

**Responsibilities**
- standardize field names
- normalize rating areas
- coerce numeric types
- attach source hashes
- merge crosswalk mappings
- deduplicate records

**Primary scripts**
- `normalize_market_data.py`
- `schema_validator.py`
- `reconcile_and_regenerate.sh`

### 3) Analytics Layer

**Purpose:** Run reusable audit models against canonical data only.

#### Base class

```python
class AuditBase:
    """
    Shared parent for all analytics modules.

    Responsibilities:
    - load canonical data
    - validate schema
    - provide common filters
    - cache intermediate results
    - export structured outputs
    """
```

#### Module 1: `audit_anomaly_detector.py`
Flags premium outliers using z-score or IQR methods.

**Output**
- `anomalies.json`

**Use cases**
- rate review triage
- manual justification requests
- consumer protection screening

#### Module 2: `market_concentration_index.py`
Calculates HHI by rating area.

**Output**
- `market_concentration.json`

**Use cases**
- competition analysis
- issuer concentration review
- market choice assessment

#### Module 3: `yoy_premium_delta_engine.py`
Compares current-year and baseline premiums.

**Output**
- `yoy_deltas.json`
- `shock_report.md`

**Use cases**
- year-over-year trend analysis
- cliff increase detection
- policymaker briefing

#### Module 4: `crosswalk_leakage_audit.py`
Checks mapping integrity between old and new plan IDs.

**Output**
- `leakage_report.json`

**Use cases**
- orphan plan detection
- new entrant validation
- discontinuation review

#### Module 5: `subsidy_affordability_mapper.py`
Estimates effective consumer cost after subsidy modeling.

**Output**
- `affordability_matrix.json`
- `affordability_dashboard.html`

**Use cases**
- affordability analysis
- income-band impact review
- consumer-facing summaries

**Purpose:** Publish artifacts and preserve a reliable release trail.

**Primary scripts**
- `deploy_wiki.sh`
- `deploy_full.sh`

- `archive_snapshot.sh`

**Release bundle**
- source code snapshot
- canonical JSON inputs

- generated outputs
- changelog
- checksums

## Data Flow Contract

1. Raw inputs are ingested.
2. Raw inputs are normalized into canonical JSON.
3. Analytics modules consume canonical JSON only.
4. Reports consume analytics outputs only.
5. Deployment publishes immutable release artifacts.

## Descriptive Placeholder Map

- `[SOURCE_A]` = CMS crosswalk input
- `[SOURCE_B]` = insurer rate filing input
- `[SOURCE_C]` = historical baseline input
- `[CANONICAL_JSON]` = normalized market dataset
- `[ANALYTICS_OUTPUT]` = module result file
- `[REPORT_ARTIFACT]` = HTML/PDF/Markdown deliverable
- `[RELEASE_TAG]` = versioned snapshot

## Non-Negotiable Design Rules

- Canonical schema first.
- Raw inputs are immutable.
- Every output must be reproducible.
- Every report must include generation time and source hash.
- Every crosswalk decision must be explainable.
- Every module must be independently testable.

- subsidy threshold math

- crosswalk reconciliation
- report generation
- release packaging

- verify JSON loads cleanly
- verify no module writes to raw input paths

- Keep assumptions explicit in code.
- Prefer JSON for internal handoff.
- Treat every source file as evidence.
- Keep all generated outputs timestamped.
